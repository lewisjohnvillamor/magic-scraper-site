Seven kinds of Next button, to practise on.

Most scrapers stop at page one because they look for a link that says “Next”. Real sites say it with an arrow, a page number, “Older posts”, another language, a class name, or a button with no address at all. Here is the same list of thirty products paged each of those ways, so you can see which ones your tool follows.

The seven

Each list is 30 items over three pages of ten. Start on the first page and crawl; anything short of 30 means the Next was missed.

01

An arrow with no word

The Next control is an icon: a chevron in a circle with an aria-label and no visible text. Tests whether your scraper reads labels, not just link text.

Expected: 30 products across 3 pages.

02

Page numbers only

A row of page numbers with the current one marked, and no Next or arrow at all. Tests whether your scraper can work out which number comes next.

Expected: 30 products across 3 pages.

03

A blog’s “Older posts”

A journal of posts, newest first, paged by Older posts → and ← Newer posts. Tests whether “next” is understood as “older” here.

Expected: 30 posts across 3 pages.

04

Next in German

The same list in German: Weiter › and ‹ Zurück, prices written 39,00 €. Tests a scraper that only knows English.

Expected: 30 products across 3 pages.

05

Next in Japanese

The same list in Japanese, paged by 次へ and 前へ, with prices in yen. Tests a scraper that only knows the Latin alphabet.

Expected: 30 products across 3 pages.

06

A class name and nothing else

An empty, styled button whose only clue is class="pagination__next" — no text, no label, the arrow drawn in CSS. Tests whether your scraper reads the markup’s own names.

Expected: 30 products across 3 pages.

07

A button, and no address

One page. Next page is a <button> that swaps the products in with JavaScript; the address never changes. Tests whether your scraper can click as well as follow links.

Expected: 30 products from 3 clicks.

About these practice lists

Why “it only scraped the first page” is the commonest complaint

A scraper that pages through a list has to find the control that goes forward, and most of them look for a link that says Next. Real sites rarely make it that easy. A theme draws an arrow icon. A blog says Older posts. A shop in Munich says Weiter, one in Osaka 次へ. A forum shows only page numbers. A framework renders an empty element whose only clue is its class name, or a button that runs JavaScript and has no address at all. Each of the seven lists above is paged one of those ways, with the same thirty products, so you can see exactly which ones a tool follows.

What each one asks of a scraper

The arrow needs the link’s aria-label (“Next page”) read, because there is no text. Page numbers need the current number found and the link to the one after it chosen — without being fooled by a row of star ratings that also reads 1 2 3 4 5. Older posts needs the direction understood: on a blog, older is forward and Newer is back. The German and Japanese lists need words in other languages. The class-only link needs the markup’s own names read. The JavaScript button needs clicking in a real page, then waiting for the list to change, because there is no URL to fetch.

A Next finder in Python

The six link-based lists can be walked with one function that tries the same clues in order: rel="next", a label or word that means forward, a class with next in it, and finally the number after the current page.

import re, requests
from urllib.parse import urljoin
from bs4 import BeautifulSoup

WORDS = re.compile(r"^(next|older|weiter|次へ|suivant|siguiente)\b|^[›»→]$", re.I)

def next_link(soup):
    for a in soup.select("a[href]"):
        label = (a.get("aria-label") or a.get_text(" ", strip=True)).strip()
        if a.get("rel") == ["next"] or WORDS.search(label) or "next" in " ".join(a.get("class", [])):
            return a["href"]
    on = soup.select_one(".pager .on")                 # page numbers only
    if on and on.get_text(strip=True).isdigit():
        a = on.find_next_sibling("a", string=str(int(on.get_text(strip=True)) + 1))
        return a["href"] if a else None

url, rows = "https://magicscraper.app/demo/pager-ja-1", 0
while url:
    soup = BeautifulSoup(requests.get(url).content, "html.parser")
    rows += len(soup.select("article"))
    href = next_link(soup)
    url = urljoin(url, href) if href else None
print(rows)   # 30

Pass .content, not .text, to BeautifulSoup: it then reads the page’s own charset, and the Japanese list does not turn into mojibake on a server that leaves the charset out of its headers. The seventh list, the JavaScript button, cannot be done this way at all; it needs a browser, or the extension.

30 items over 3 pages from every list. Ten means the Next was missed; twenty usually means a crawler went forward and then back.
